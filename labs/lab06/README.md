### 1. Схема и eBGP-сессии

![](scheme.png)

| Сессия | Адреса | AS | Задание |
|---|---|---|---|
| R14 - R22 | 101.0.0.2 - 101.0.0.1 | 1001 - 101 | Москва - Киторн |
| R15 - R21 | 30.1.0.2 - 30.1.0.1 | 1001 - 301 | Москва - Ламас |
| R22 - R21 | 101.0.0.5 - 101.0.0.6 | 101 - 301 | Киторн - Ламас |
| R21 - R24 | 30.1.0.5 - 30.1.0.6 | 301 - 520 | Ламас - Триада |
| R18 - R24 | 52.0.1.2 - 52.0.1.1 | 2042 - 520 | С.-Петербург - Триада |
| R18 - R26 | 52.0.1.6 - 52.0.1.5 | 2042 - 520 | С.-Петербург - Триада |

- Сессии строятся между адресами непосредственно подключённых интерфейсов: для eBGP это стандартный вариант, `ebgp-multihop` и маршруты до Loopback соседа не нужны.
- **Router ID** равен адресу Loopback0.
- Линк R22-R23 (Киторн - Триада) по заданию в BGP не участвует.
- iBGP между R14 и R15, а также внутри Триады в этой работе не настраивался, это тема следующей работы. Для задачи он пока не нужен: каждый роутер, которому нужны маршруты, получает их напрямую от eBGP-соседа.

### 2. Что анонсируется

| AS | Префикс | Кто анонсирует |
|---|---|---|
| 1001 Москва | 100.1.0.0/24 | R14, R15 |
| 2042 С.-Петербург | 20.42.0.0/24 | R18 |
| 101 Киторн | 101.0.0.0/16 | R22 |
| 301 Ламас | 30.1.0.0/16 | R21 |
| 520 Триада | 52.0.0.0/16 | R24, R26 |

Каждая AS анонсирует только свой блок целиком, а не отдельные подсети. Команда `network` в BGP анонсирует префикс только при точном совпадении с маршрутом в таблице маршрутизации. Поэтому для каждого блока заведён статический маршрут на `Null0` с AD 254: он гарантирует наличие префикса в таблице, но проигрывает любому реальному маршруту, а трафик в неиспользуемую часть блока отбрасывается на границе AS.

Внутренние сети офисов (`10.0.0.0/8`) в BGP не анонсируются: это частные адреса. Для проверки связности между офисами на пограничных роутерах добавлены интерфейсы Loopback1 с адресами из публичных блоков:

| Роутер | Loopback1 |
|---|---|
| R14 | 100.1.0.14/32 |
| R15 | 100.1.0.15/32 |
| R18 | 20.42.0.18/32 |

Loopback1 на R14 и R15 добавлены в OSPF (area 0). Москва анонсирует один и тот же блок через двух провайдеров, поэтому ответ на пакет, отправленный с R14, может прийти через Ламас на R15. Через OSPF R15 знает, где находится `100.1.0.14`, и доставит ответ.

### 3. Примеры настройки

R14 (Москва, сессия с Киторном):
```
interface Loopback1
 description Public / BGP test
 ip address 100.1.0.14 255.255.255.255
 ip ospf 1 area 0
!
ip route 100.1.0.0 255.255.255.0 Null0 254
!
router bgp 1001
 bgp router-id 10.10.255.14
 bgp log-neighbor-changes
 neighbor 101.0.0.1 remote-as 101
 neighbor 101.0.0.1 description R22 Kitorn
 !
 address-family ipv4
  network 100.1.0.0 mask 255.255.255.0
  neighbor 101.0.0.1 activate
 exit-address-family
```

R21 (Ламас, три соседа):
```
ip route 30.1.0.0 255.255.0.0 Null0 254
!
router bgp 301
 bgp router-id 30.1.255.21
 bgp log-neighbor-changes
 neighbor 30.1.0.2 remote-as 1001
 neighbor 30.1.0.2 description R15 Moscow
 neighbor 101.0.0.5 remote-as 101
 neighbor 101.0.0.5 description R22 Kitorn
 neighbor 30.1.0.6 remote-as 520
 neighbor 30.1.0.6 description R24 Triada
 !
 address-family ipv4
  network 30.1.0.0 mask 255.255.0.0
  neighbor 30.1.0.2 activate
  neighbor 101.0.0.5 activate
  neighbor 30.1.0.6 activate
 exit-address-family
```

R18 (С.-Петербург, два линка в Триаду):
```
interface Loopback1
 description Public / BGP test
 ip address 20.42.0.18 255.255.255.255
!
ip route 20.42.0.0 255.255.255.0 Null0 254
!
router bgp 2042
 bgp router-id 10.20.255.18
 bgp log-neighbor-changes
 neighbor 52.0.1.1 remote-as 520
 neighbor 52.0.1.1 description R24 Triada
 neighbor 52.0.1.5 remote-as 520
 neighbor 52.0.1.5 description R26 Triada
 !
 address-family ipv4
  network 20.42.0.0 mask 255.255.255.0
  neighbor 52.0.1.1 activate
  neighbor 52.0.1.5 activate
 exit-address-family
```

R14 получает от Киторна префиксы всех AS. Путь до С.-Петербурга проходит через Киторн, Ламас и Триаду:

#### Связность между офисами

Пограничные роутеры Москвы и С.-Петербурга доступны друг другу по адресам из публичных блоков:
```
R14#ping 20.42.0.18 source Loopback1
Packet sent with a source address of 100.1.0.14
!!!!!
Success rate is 100 percent (5/5), round-trip min/avg/max = 1/1/1 ms

R14#traceroute 20.42.0.18 source Loopback1
Tracing the route to 20.42.0.18
  1 101.0.0.1 [AS 101] 0 msec 0 msec 1 msec
  2 101.0.0.6 [AS 101] 1 msec 0 msec 1 msec
  3 30.1.0.6 [AS 301] 1 msec 0 msec 1 msec
  4 52.0.1.2 [AS 520] 1 msec *  1 msec

R18#ping 100.1.0.15 source Loopback1
Packet sent with a source address of 20.42.0.18
!!!!!
Success rate is 100 percent (5/5), round-trip min/avg/max = 1/1/1 ms
```

Трассировка идёт R14 → R22 (Киторн) → R21 (Ламас) → R24 (Триада) → R18. Метка `[AS ...]` у каждого хопа показывает AS, которой принадлежит адрес по данным BGP: адреса на линках между провайдерами взяты из блока одного из них.
